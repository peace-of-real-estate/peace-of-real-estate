# Varlock + Bitwarden SSOT + CI-built images

**End state:** BWS holds all secret values; repo holds only `bitwarden("uuid")`
refs (safe to commit); Blacksmith CI builds the Docker image (secrets resolved
at build, baked as encrypted blob) and pushes to GHCR; Railway deploys the image
and holds only `_VARLOCK_ENV_KEY` (target) + Railway-managed `DATABASE_URL`. CI
test jobs unchanged (`.env.test` dummies).

**Decisions:** separate dev/prod creds · `DATABASE_URL` stays Railway-managed ·
BWS projects `pre-dev` + `pre-prod` (shared secrets in `pre-dev`; local token
reads `pre-dev`, Railway/CI token reads both) · local token via
`varlock(prompt)` in `.env.local` · dev `RESEND_API_KEY` = `.env.local` value
(dev.local one is stale) · GHCR registry · all-at-once · runtime BWS token:
spike, accept either outcome.

## A. BWS + varlock

1. **BWS console (user):** projects `pre-dev`/`pre-prod`; machine accounts
   (local: read `pre-dev`; CI: read both); add secrets (`BETTER_AUTH_SECRET`×2,
   `BETA_PASSWORD`, `GOOGLE_CLIENT_ID/SECRET`, `STRIPE_SECRET_KEY`×2,
   `STRIPE_WEBHOOK_SECRET`×2, `STRIPE_INTRO_UNLOCK_PRICE_ID`×2,
   `RESEND_API_KEY`×2, Tigris `AWS_ACCESS_KEY_ID/SECRET_ACCESS_KEY`,
   `FROM_EMAIL`); record UUIDs; generate + store `_VARLOCK_ENV_KEY`
   (`vp exec varlock generate-key`).
2. **`.env.schema`:** `@plugin(@varlock/bitwarden-plugin)` +
   `@initBitwarden(accessToken=$BITWARDEN_ACCESS_TOKEN)` + token item
   (`@type=bitwardenAccessToken`); refs for shared secrets (`BETA_PASSWORD`,
   Google OAuth); fix stale `ADMIN_EMAILS` comment; remove unused `AI_*` keys.
3. **`.env.development` / `.env.production`:** per-env refs.
4. **Local files (user edits):** `.env.local` → only
   `BITWARDEN_ACCESS_TOKEN=varlock(prompt)`; `.env.development.local` → only
   auto-generated `AWS_ENDPOINT_URL`.
5. **Repo cleanup:** `git rm --cached env.d.ts`; add `@varlock/bitwarden-plugin`
   dep; slim `scripts/bootstrap.sh`; document workflow in `AGENTS.md` (BWS
   canonical; GitHub `BETA_PASSWORD` secret manually synced on rotation).

## B. CI-built images → Railway

6. **`Dockerfile` + `.dockerignore` (new):** node 24 + corepack pnpm + `vp` CLI;
   `pnpm install`; `vp build` with `RUN --mount=type=secret` for
   `BITWARDEN_ACCESS_TOKEN` + `_VARLOCK_ENV_KEY` (never in layers; resolved env
   baked encrypted into `.output`); keep repo + node_modules in final stage
   (preDeploy migrations need `tsx scripts/` + drizzle).
7. **`.github/workflows/deploy.yml` (new, Blacksmith runners):** on push to
   main + PRs — `useblacksmith/setup-docker-builder` + build-push-action (layer
   cache), push `ghcr.io/<owner>/peace-of-real-estate:{sha,pr-N}`; then call
   Railway GraphQL API (`RAILWAY_API_TOKEN` GH secret) to point the env's
   service at the image tag and trigger deploy. **Riskiest piece:** per-PR env
   wiring — spike early.
8. **`railway.toml`:** drop `[build]` section (image deploy); keep
   `preDeployCommand` (migrate+init), `startCommand`.
9. **Railway dashboard (user):** switch service source to GHCR image + registry
   credential; set `_VARLOCK_ENV_KEY`; delete other manual vars; keep
   `DATABASE_URL`/`RAILWAY_*`.
10. **`e2e.yml`:** unchanged if Railway still posts `deployment_status` for
    API-triggered image deploys (verify in spike); else trigger e2e from
    `deploy.yml` via `workflow_dispatch`.

## Verify (in order)

1. `vp exec varlock load --agent` + `varlock audit` — refs resolve locally.
2. `vp check && vp test` — CI path needs no BWS.
3. `vp dev` smoke: Google auth, Stripe flow, S3 avatar, email send.
4. `docker build` locally with secrets mounts; inspect image for plaintext
   secrets (`varlock:v1:` prefix present, no raw values).
5. **Spike:** deploy image to a Railway PR env with only `_VARLOCK_ENV_KEY` —
   does app boot and see runtime `DATABASE_URL`? If no, add
   `BITWARDEN_ACCESS_TOKEN` to Railway (accepted fallback).
6. Full PR flow: image builds, Railway PR env deploys it, e2e.yml passes.
7. `varlock scan --staged` before commit.
